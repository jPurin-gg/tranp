1. **P1 bug — Unbounded SSE connections allow resource exhaustion.** [internal/server/server.go:194](/home/lab_purin/workspace/tranp/internal/server/server.go:194), [internal/server/room.go:110](/home/lab_purin/workspace/tranp/internal/server/room.go:110)  
   One valid seat cookie can open unlimited streams. Each retains a handler, channel, ticker, and connection; every action broadcasts to all of them while holding the room mutex. An attacker can create their own room and exhaust the container’s 128 MB limit or make room operations very expensive. **Fix:** enforce per-seat and global stream limits, preferably replacing an existing connection when the same seat reconnects.

2. **P2 should fix — Room creation can exhaust capacity for two hours, and its limit is non-atomic.** [internal/server/server.go:115](/home/lab_purin/workspace/tranp/internal/server/server.go:115), [internal/server/room.go:202](/home/lab_purin/workspace/tranp/internal/server/room.go:202)  
   Anyone can issue 1,000 creation requests and prevent legitimate users from creating rooms until expiry. Concurrent requests can also all pass `count()` before inserting, exceeding `maxRooms`. **Fix:** check capacity and insert under the same registry lock; rate-limit creation and give never-joined rooms a much shorter lifetime.

3. **P2 should fix — Expiry and room admission are not atomic.** [internal/server/room.go:225](/home/lab_purin/workspace/tranp/internal/server/room.go:225), [internal/server/server.go:128](/home/lab_purin/workspace/tranp/internal/server/server.go:128)  
   A handler can retrieve an idle room, then the sweeper can remove it before the handler joins or subscribes. Alternatively, a subscription can arrive between `idle()` and `close()` and be immediately closed. A late subscriber can even register after `close()` and watch an orphan room that future POSTs cannot find. **Fix:** add a closed flag checked under the room lock by admission and mutation methods; atomically check expiry and mark the room closed before removing it. Reject operations on closed rooms.

4. **P2 should fix — Seat cookies expire while their rooms remain active.** [internal/server/server.go:165](/home/lab_purin/workspace/tranp/internal/server/server.go:165)  
   Cookie lifetime is two hours from `/join`, but SSE activity can preserve a room indefinitely. After two hours, POSTs lose authentication; a reload tries to join without the cookie and receives “満席” because both tokens remain occupied. Rematches do not refresh the cookie. **Fix:** separate credential lifetime from idle-room retention, using session cookies or a longer lifetime with renewal.

5. **P2 should fix — Request bodies and stream writes have no time bounds.** [cmd/tranp/main.go:35](/home/lab_purin/workspace/tranp/cmd/tranp/main.go:35), [internal/server/server.go:197](/home/lab_purin/workspace/tranp/internal/server/server.go:197), [internal/server/server.go:302](/home/lab_purin/workspace/tranp/internal/server/server.go:302)  
   `ReadHeaderTimeout` does not bound body reads. An authenticated caller can send an unfinished JSON body and retain a handler indefinitely despite the 1 KB size limit. SSE writes or flushes can likewise block on a stalled connection, retaining its subscription and preventing room expiry. **Fix:** set bounded read deadlines for POST bodies and renew a bounded write deadline for each SSE write/flush. Expose `Unwrap()` on `statusWriter` so `http.ResponseController` can reach the underlying writer.

6. **P2 should fix — Disconnected clients can submit actions against stale game state.** [web/static/app.js:94](/home/lab_purin/workspace/tranp/web/static/app.js:94), [web/static/app.js:146](/home/lab_purin/workspace/tranp/web/static/app.js:146), [internal/server/server.go:243](/home/lab_purin/workspace/tranp/internal/server/server.go:243)  
   Stream errors only dim the header; card and navigation handlers continue using the last snapshot. POST connectivity can recover before SSE, allowing a click on an old board to flip a card in a newer turn or rematch. The server validates the seat and current turn, but not which game/turn the action targeted. **Fix:** disable actions until a fresh snapshot arrives after reconnect, and include game/turn identifiers in actions that the server validates under the room lock.

7. **P2 should fix — Swipe recognition does not suppress click actions.** [web/static/app.js:45](/home/lab_purin/workspace/tranp/web/static/app.js:45), [web/static/app.js:115](/home/lab_purin/workspace/tranp/web/static/app.js:115)  
   The passive touch handlers request navigation without cancelling or suppressing the subsequent click. On browsers that synthesize a click for the gesture, swiping from a card can also flip it; which region the click targets depends on whether the SSE update has arrived. Swipes starting on navigation buttons have the same conflict. **Fix:** use one pointer gesture implementation with a movement threshold, cancellation handling, and explicit click suppression after a swipe.

8. **P2 should fix — Rapid navigation uses stale absolute destinations and permits reordered actions.** [web/static/app.js:101](/home/lab_purin/workspace/tranp/web/static/app.js:101)  
   Two quick “next” taps before SSE updates both calculate the same destination, so one tap disappears. Navigation and flip requests can also overlap: if a flip reaches the server before an earlier navigation request, the later navigation can move both screens away from the card just revealed. `await` inside each callback does not serialize separate callbacks. **Fix:** serialize outgoing actions and reconcile them with confirmed snapshots; disable or queue navigation while a request is outstanding.

9. **P2 should fix — Idle retention is measured from the last action, not the last viewer.** [internal/server/room.go:118](/home/lab_purin/workspace/tranp/internal/server/room.go:118), [internal/server/room.go:173](/home/lab_purin/workspace/tranp/internal/server/room.go:173)  
   Subscribing and unsubscribing do not update `touched`. A room watched for more than two hours without actions becomes immediately eligible for deletion when its last stream disconnects. A brief network interruption can therefore destroy the room instead of preserving it for the documented two hours without viewers. **Fix:** update the inactivity timestamp when the last subscriber leaves, and perform that transition under the room lock.
