# 技術選定

2 人対戦の神経衰弱（tranp）の決定事項の記録。2026-11-02。

## 要件（決まった順）

| 項目 | 決定 |
| --- | --- |
| 形式 | 2 人の対戦。別々の端末からネット越し |
| つなぎ方 | 部屋を作って URL を相手に送る。アカウントなし |
| 置き場所 | 自宅の LXC ＋ Cloudflare Tunnel（dieyet と同じ） |
| 端末 | スマホ横持ち |
| 盤面 | 52 枚を 4 区画に分け、画面には 1 区画だけ。区画を移動して遊ぶ |
| 観戦 | 手番の人の操作（区画移動・めくり）が相手の画面もそのまま動かす。手番でない側は見るだけ |
| ルール | 同じ数字ならマーク違いでも成立。ジョーカーなし。揃えばもう一度、違えば交代。多く取った方が勝ち |

細かい点はこちらで決めた: 先手は部屋を作った側、再戦は前回の後手が先手、2 枚目の表示は揃って 0.9 秒・不揃いで 1.5 秒、空いた部屋は 2 時間で消す。

## スタック

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| サーバー | Go（標準ライブラリのみ） | 利用者の指定。dieyet・hrs_shift と同じで、外部モジュールゼロ |
| フロント | 素の JS、バイナリに埋め込み | 利用者の指定。画面は 3 枚だけでフレームワークは要らない |
| リアルタイム配信 | SSE ＋ POST | 標準ライブラリだけで済む。WebSocket は外部パッケージが要るうえ、操作は秒に数回以下なので双方向は不要 |
| DB | なし（メモリ） | 部屋は数十分で終わる。永続化するものがない |
| 席の識別 | 部屋ごとの HttpOnly Cookie | URL にトークンを載せない。再読み込みで同じ席に戻れる |

比較表は作っていない。利用者が「Go と素の JS でいい」と指定したため（2026-11-02）。
