# 技術選定

2 人対戦の神経衰弱（tranp）の決定事項の記録。2026-11-02。

## 要件（決まった順）

| 項目 | 決定 |
| --- | --- |
| 形式 | 2 人の対戦。別々の端末からネット越し |
| つなぎ方 | 部屋を作って URL を相手に送る。アカウントなし |
| 置き場所 | 自宅の LXC ＋ Cloudflare Tunnel（dieyet と同じ） |
| 端末 | スマホ横持ち |
| 盤面 | 52 枚を 2×2 の 4 区画に分け、画面には 1 区画だけ。上下左右に移動して遊ぶ（2026-11-03 に横一列から 2×2 へ変更） |
| 観戦 | 手番の人の操作（区画移動・めくり）が相手の画面もそのまま動かす。手番でない側は見るだけ |
| ルール | 同じ数字ならマーク違いでも成立。ジョーカーなし。揃えばもう一度、違えば交代。多く取った方が勝ち |

細かい点はこちらで決めた: 先手は部屋を作った側、再戦は前回の後手が先手、2 枚目の表示は揃って 0.9 秒・不揃いで 1.5 秒、空いた部屋は 2 時間で消す。

## スタック

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| サーバー | Go（標準ライブラリのみ） | 利用者の指定。dieyet・hrs_shift と同じで、外部モジュールゼロ |
| フロント | 素の JS、バイナリに埋め込み | 利用者の指定。画面は 3 枚だけでフレームワークは要らない |
| リアルタイム配信 | SSE ＋ POST | 標準ライブラリだけで済む。WebSocket は外部パッケージが要るうえ、操作は秒に数回以下なので双方向は不要 |
| DB | なし（メモリ） | 部屋は数十分で終わる。永続化するものがない |
| 席の識別 | 部屋ごとの HttpOnly Cookie | URL にトークンを載せない。再読み込みで同じ席に戻れる |

比較表は作っていない。利用者が「Go と素の JS でいい」と指定したため（2026-11-02）。

## レビュー（2026-11-02）

第 1 版を Codex に読み取り専用でレビューさせた（[原文](Codexレビュー.md)）。9 件すべて対応した。

| 指摘 | 対応 |
| --- | --- |
| 1 席で SSE を無限に開ける | 部屋ごとに 6 本まで。超えたら 429 |
| 部屋を 1000 個作られると 2 時間詰まる。上限チェックが非アトミック | 作成はトークンバケット（毎秒 1、バースト 30）。上限チェックと登録を同じロックで。相手が来なかった部屋は 15 分で消す |
| 掃除と参加・購読が競合する | 部屋に closed フラグ。参加・購読・操作は部屋のロック内で確認し、閉じた部屋は 404 |
| Cookie が 2 時間で切れて部屋より先に死ぬ | Cookie は 24 時間、参加のたびに更新 |
| ボディ読み取りと SSE 書き込みに期限がない | `http.ResponseController` で読み 5 秒・書き 10 秒の期限 |
| 切断中の古い盤面で操作できる | 配信に `seq` を付け、操作は見た `seq` を送る。違えば 409。切断中は操作しない |
| スワイプのあとにクリックも飛ぶ | touchend で `preventDefault`。縦方向の動きが大きければスワイプ扱いしない |
| 連打で移動先が重なる・操作が追い越す | 操作は 1 つずつ（返事が来るまで次を送らない）＋ `seq` |
| 空き判定が最後の操作時刻だけ | 購読が切れた時刻も更新 |
